# Aura Frames Memory
Important `aura_frames` keys:
- Session/UI: `last_tab_index`, `last_frames_node`, `last_profile_name`
- Global AF settings: `short_threshold`, `learned_helpful_durations`, `enable_blizz_buffs`, `enable_blizz_debuffs`, `snap_to_grid`, `show_grid`, `show_bar_section_outlines`
- Timer fallback: `timer_number_font`, `timer_number_font_size`, `timer_number_font_bold`
- Preset per-category keys: `<setting>_<category>` such as `show_static_long`, `color_debuff`, `scale_short`
- Growth keys: presets store `growth_icon_<category>` and `growth_bar_<category>`; custom frames use flat `growth_icon` and `growth_bar`.
- OOC fade: preset frames use `fade_ooc_<category>`, `ooc_alpha_<category>`, `fade_delay_<category>`, and `fade_length_<category>`; custom frames use flat `fade_ooc`, `ooc_alpha`, `fade_delay`, and `fade_length`. `af_defaults.lua` owns the `ooc_alpha` range/step constants (`0.00..1.00`, step `0.05`) so the slider and runtime clamp stay aligned; zero lets users fully hide a faded frame background. Fade timing defaults are 2s delay and 3s fade length.
- Aura Frames OOC fade immediately restores full alpha while the mouse is over the move handle, resize handle, or visible icons/bars; leaving the visible frame controls resumes the configured delay/fade.
- Duration Swipe keys: preset frames use `timer_swipe_<category>` and custom frames use `timer_swipe`; Bar Mode suppresses icon Aura-duration swipes regardless of the saved value, and CDM cooldown-mode ability swipes intentionally remain visible when Duration Swipe is off. Managed Icon-mode AuraButtons create one Cooldown during initialization, bind it once through `SetDurationCooldown()`, and leave Aura timing and visibility entirely to Blizzard; only OOC `SetDrawSwipe()` styling follows the saved preference.
- Aura cancellation uses plain right-click. Static / Long Buffs binds Blizzard's native `RightButtonUp` AuraButton cancellation during initialization. Custom frames use the addon-owned out-of-combat `M.try_cancel_aura_icon()` path and resolve the clicked Aura through a fresh `HELPFUL|CANCELABLE` scan. There is no modifier setting.
- Positions: `aura_frames.positions.<category> = { point, x, y }`
- Custom frames: array entries with `id`, `name`, filter fields, flat presentation keys, and `position`
- Profiles: complete Aura Frames snapshots excluding editor/session state such as selected tabs/nodes, grid visibility, and debug outlines

## Ownership
- Built-in category metadata lives in `M.FRAME_DEFS` (`af_defaults.lua`). Derive category lists, labels, CDM viewer names, preset key names, and test labels from it.
- `M.AURA_FRAME_LIMIT = 40` is the fixed internal ceiling for managed groups, custom/CDM pools, rendering, and scans. Aura count is not adjustable, saved, or profiled; frame implementations own selection and layout beneath that ceiling.
- Stack-count typography uses the per-frame `stack_number_font`, `stack_number_font_size`, `stack_number_font_bold`, `stack_number_font_outline`, and `stack_color` settings. Timer typography has the corresponding `timer_number_font_outline` setting. Aura Frames defaults both Timer and Stack font selections to `Game Default`; both outline settings default on and use WoW's native black `OUTLINE` font flag. `M.apply_stack_font_style` is the shared stack application path for managed and addon-rendered custom AuraButtons. Selectable fonts, bold faces, dropdown previews, and semantic `Game Default` roles come from the addon-wide `functions/font_catalog.lua`: Timer uses Blizzard `GameFontNormalSmall`, while Stack uses `NumberFontNormal`; both resolve the native face through `GetFont()` while configured size and outline remain independent. Icon stack anchors consume `M.ICON_STACK_INSET` (`right=2`, `bottom=2`), matching Blizzard's BuffFrame while keeping future adjustment centralized; bar stacks remain centered in their dedicated slot.
- The rounded/chamfered background investigation remains in `ToDo/background_shapes.md`. Do not re-add that option without a dedicated tintable asset or NineSlice plan.
- Active unfinished Aura Frames implementation, live acceptance, and performance decisions are consolidated in `ToDo/aura_frames_remaining_work.md`; the full 12.1 assessment is retained under `internal_dev/working_docs/reference/` as historical context.
- Preset categories: `debuff`, `short`, `static_long`, `timed`, `essential`, `utility`, `tracked_buffs`, `tracked_bars`.
- CDM-backed categories: `essential`, `utility`, `tracked_buffs`, `tracked_bars`.
- First-install visible frames are `short` and `debuff`. Static / Long Buffs, Timed Buffs, and CDM categories default disabled.
- Preset DB keys use `aura_frames.<setting>_<category>`; custom frame entries use flat keys.
- `M.normalize_saved_colors()` clamps preset and custom `color`, `bar_bg_color`, `bar_text_color`, `bg_color`, and `timer_color` components at startup and profile load. Keep this normalization before runtime-config caching so edited or malformed saved values cannot reach frame color APIs unchanged.
- Preset and custom frame settings share the same presentation model via normalized `frame_config.keys` and `build_frame_settings_panel()` in `af_gui_frame_builders.lua`.
- `af_frame_config.lua` owns the explicit preset/custom frame profile field lists plus mode-aware growth default application, logical-key selection, and runtime resolution. Category-specific icon/bar growth defaults remain visible beside each category in `M.FRAME_DEFS`; defaults, GUI, profiles, addon-rendered layout, and managed layout consume the shared configuration helpers instead of repeating key rules. Returning from Bar Mode restores the saved Icon Mode direction, or resolves to `RIGHT` when no icon direction has been saved.
- Aura update logic is split by runtime responsibility: `af_logic_ticker.lua` owns visible icon timer/bar ticking, `af_logic_native_visibility.lua` owns Blizzard/native BuffFrame, DebuffFrame, and CooldownViewer visibility suppression, `af_background.lua` owns all Aura frame-background policy and rendering, and `af_logic_main.lua` owns runtime config cache, OOC fade, and the main per-frame aura refresh pipeline.
- `af_managed.lua` is the thin WoW 12.1 managed-Aura lifecycle boundary: availability, container creation, group/slot initialization tracking, safe accessibility checks, and module lifecycle gating only. `AuraContainer:SetEnabled` controls processing separately from visibility, so every lifecycle transition must keep both states synchronized. Capability code calls Blizzard AuraContainer APIs visibly; do not grow this into a generic renderer or hidden dispatcher.
- `af_managed_presets.lua` owns the shared native presentation for Short Buffs, Static / Long Buffs (`static_long`), Timed Buffs, and Debuffs. Short uses `HELPFUL`, native `candidateFilters.maxDuration = short_threshold`, and native `ExpirationOnly`/`Normal` ordering; the default threshold is 300 seconds, measures total rather than remaining duration, updates both immutable presentation groups through `SetAuraGroupCandidateFilters`, and appears in its mover tooltip. Static / Long uses `HELPFUL` plus the learned `includeSpellIDs` map. Timed uses `HELPFUL` plus `maxDuration = math.huge`, whose Blizzard implementation excludes permanent/duration-zero Auras; Debuffs uses `HARMFUL`. Managed presets do not inspect live Aura timing. Each backend preinitializes immutable Bar and Icon groups, activates only the selected group, and reuses the backend across OOC presentation changes. Bars bind native icon/name/duration/stack/fill; icon cells bind native icon/duration/stack. Category-owned Font objects allow OOC text styling without mutating constrained AuraButtons or Blizzard duration values.
- `af_managed_cdm.lua` owns CDM records and active-Aura transport. It combines effective saved category/order with public cooldown metadata through the guarded boundary documented in `## Runtime Gates And Refresh`. Aura mode uses one compact native AuraGroup per cooldown ID so empty groups collapse while CDM order remains stable; every group layout must include its explicit icon/bar `elementWidth` and `forceNewLine = false` so Blizzard can flow separate groups horizontally before wrapping. Only the selected Icon or Bar mode may call the shared container-layout helper: configuring an inactive Bar group after an active Icon group overwrites the container axis and forces DOWN growth. Cooldown mode keeps public-API-backed addon cooldown cells and overlays one stable native AuraSlot per cooldown ID. Refresh from CDM data-loaded, hotfix, layout-save, and spell-override events, deferring structural work until OOC. Never read CDM child Aura instance IDs or `AuraData`.
- 2026-08-16 CDM growth incident: explicit group width and `forceNewLine = false` did not fix Tracked Buff icons growing DOWN because those fields were never the final authority. `make_group_layout()` calls `configure_managed_presentation_layout()`, which mutates the shared AuraContainer flow axis, anchor, direction, and line size. The per-record refresh processed Icon and then Bar; letting the inactive Bar pass call that helper made its vertical layout win last. Preserve the `is_selected_mode` gate around `SetAuraGroupLayout()` and audit any future helper that appears group-local for container-wide side effects.
- `af_learned_buffs.lua` owns the separate Static / Long learner. While the module is active and the player is outside combat, its bucketed listener scans readable `HELPFUL` player Auras, rejects secret/malformed identity and duration values, and stores the latest total duration in global `learned_helpful_durations`. Duration zero or greater than `short_threshold` enters the native inclusion map; duration at or below the threshold removes that spell from the displayed class. Unknown spells remain hidden until learned. Cache revision and threshold changes refresh both immutable managed groups outside combat; clearing is blocked in combat. Module reset explicitly queues a fresh observation after replacing the cache so active buffs repopulate without waiting for another `UNIT_AURA`. The learner stops with module runtime and never consumes `UNIT_AURA` payload Aura data.
- Managed AuraButtons use their native tooltip path with mouse motion enabled in and out of combat. Keep `SetHideTooltipInCombat(false)` explicit; Blizzard's private AuraButton mixin owns restricted Aura data, tooltip population, refresh, and hiding. Do not add addon `OnEnter`/`OnLeave` handlers or reconstruct Aura tooltip data; native hover is also the safe diagnostic for identifying which Aura Blizzard bound to an unexpected icon.
- Managed bar foreground color is set during initialization and reapplied only OOC to accessible AuraButtons. Resolve it through the shared Aura/global color pipeline and cache RGBA on each StatusBar so unchanged settings refreshes do not write again.
- Managed containers are auto-sizing flow frames. Seed them at `1x1` from one owner-frame corner, then set the capability's flow axis, anchor, growth, wrap size, and group layout explicitly; do not use `SetAllPoints` on an `AuraContainer`.
- `addon.GetGrowthDirection()` and `addon.CreateGrowthDirectionDropdown()` in `functions/growth_direction.lua` own canonical UP/DOWN/LEFT/RIGHT layout metadata and control construction. Addon-rendered and managed Aura layouts both translate that shared result into their geometry; move controls are deliberately independent from aura growth.
- Icon and Bar modes remember growth independently. Icon mode exposes all four directions through `growth_icon`; Bar Mode exposes DOWN/UP through `growth_bar`. Mode toggles switch the dropdown value/options without overwriting either saved direction; runtime resolution normalizes malformed horizontal Bar values to DOWN.
- Managed presentation backends intentionally own no Aura events. The separate Static / Long learner owns its OOC-only `PLAYER_ENTERING_WORLD`, `UNIT_AURA`, specialization, and regen listener. Runtime startup must explicitly refresh addon-owned shell visibility after enabling the managed engine. Parent shells retain only `PLAYER_REGEN_DISABLED/ENABLED` for fade behavior; pass the event's explicit combat state into the fade helper instead of immediately re-querying `InCombatLockdown()`. Apply each fade value to both shell and aggregate managed AuraContainer because constrained AuraButtons do not reliably inherit shell alpha; cache container alpha on the addon-owned backend and never mutate individual protected AuraButtons for fading.
- `/lst status aura_frames` includes one `managed=...` record per managed backend with unit, feature, engine, container, group, slot, created-AuraButton, and accessible-AuraButton counts. Never inspect `AuraButton:IsShown()` and never attach `OnShow`/`OnHide` scripts: Blizzard drives `AuraButton:SetShown()` with a secret boolean, and any addon script handler makes that native write illegal.
- `af_functions.lua` is still a broad Aura Frames shared-helper bucket. Its current ownership includes CDM viewer lookup, frame positioning, custom frame setup, frame/category setting fallback resolution, aura cancellation, timer behavior, and timer-boundary normalization. Prefer splitting future work by subsystem instead of adding more helpers there; likely split names are `af_frame_helpers.lua`, `af_settings_helpers.lua`, `af_cancel.lua`, and `af_timer_helpers.lua`.


## Runtime Gates And Refresh
- Runtime module gating is centralized through `M.MODULE_KEY`, `M.is_runtime_enabled()`, and `M.stop_runtime()`. Keep Settings Module Enabler checks routed through those helpers instead of repeating direct `addon.is_module_enabled("aura_frames")` checks across runtime files.
- Saved-data preparation is independent from runtime enablement: `ADDON_LOADED` always attaches `M.db`, applies defaults, and normalizes saved data so the locked settings page can build while disabled. Only `ensure_module_started()` may create Aura frames, and runtime services remain enable-gated.
- 2026-08-15 in-game acceptance: after disabling Aura Frames and reloading, its locked settings page builds without error; re-enabling starts the runtime normally from the prepared saved-data table.
- Frame processing is enabled-rooted. Disabled frames must not do move-shell work, previews, scans, render, layout, or CDM viewer prep.
- Every newly constructed Aura frame shell, move handle, and resizer starts hidden; only the frame update path may show them from saved enabled/move state. Disabled startup events intentionally return early, so relying on CreateFrame's default shown state exposes a white move shell after reload.
- Managed AuraButtons must be completely constructed and bound inside their AuraGroup `initializeFrame` callback. Later button writes are allowed only after `M.is_managed_aura_button_accessible()` succeeds; container/group configuration stays explicit in the owning capability.
- Managed Short Buffs, Static / Long Buffs, Timed Buffs, and Debuffs route through `update_managed_preset_frame()` before the addon-rendered `self.icons` gate except while their addon-owned Test Aura is active. Each fully managed frame precreates one mock visual; preview mode keeps native content visible, renders the mock through the normal addon presentation path, gives it a separate shell-owned background cell resolved from the same Frame BG visibility/color policy, and anchors that cell outside the native origin on the side opposite the saved growth direction. CDM frames remain hybrid and retain their full cooldown/preview pool. All managed containers own live Aura updates; addon-owned shells own preview, enabled/move-control visibility, and out-of-combat alpha.
- Re-enabling the Aura Frames module must invalidate custom/sorted scan caches, restart runtime services, then refresh/rebind all existing frames.
- Blizzard `BuffFrame` / `DebuffFrame` suppression uses one hidden addon-owned parent. `set_blizz_buffs_enabled()` / `set_blizz_debuffs_enabled()` capture each original parent, reparent only out of combat, and restore only while the frame remains under LsTweeks' suppressor; combat changes queue through the shared Blizzard-setting event frame. This preserves Blizzard shown state, events, scripts, and Aura processing while suppressing both rendering and descendant hitboxes. Do not alpha-hide, mutate descendant mouse state, install `OnShow` hooks, call `Hide()` / `Show()` or `UpdateShownState()`, unregister events, replace scripts, or drive Edit Mode settings: direct hiding tainted secret expiration-time arithmetic, alpha hiding left invisible Aura hitboxes, and `UpdateSystemSettingValue()` silently returns before Edit Mode `systemInfo` initialization while `pcall` still reports success. BasicBuffHide independently validates the hidden-parent technique in current 12.1 code; LsTweeks contains no copied BasicBuffHide code.
- 2026-08-15 in-game acceptance: Blizzard BuffFrame/DebuffFrame suppression and restoration passed across checkbox changes, reload, combat deferral, and Aura Frames module disable with no invisible hitboxes, duplicate frames, blocked actions, or Lua errors.
- Tooltip ownership: route Aura icons and settings help through `functions/tooltip.lua`; the complete safety contract and incident history live in `## Aura Tooltips`.
- Use `M.get_frame_activity_state()` for activity decisions. CDM frames have no viewer-preparation activity state.
- Addon-rendered UNIT_AURA work is batched at `UPDATE_INTERVALS.aura_event_bucket`; custom timers and CDM cooldown-mode entries tick at `UPDATE_INTERVALS.aura_visible_icon_tick`. Managed preset and CDM active-Aura animation uses WoW's native duration bindings.
- General CPU profiling workflow lives in `internal_dev/tests_tools/cpu_profiles/profiling_workflow.md`; this file keeps only Aura Frames-specific profiling conclusions.
- Aura Frames registers separate `frame:<id>` and `bar:<id>` Shared Colors targets for every built-in and custom frame. Custom targets register on create/load, update labels on rename, and unregister on deletion. Resolution occurs while building cached runtime configuration; `M.on_shared_color_changed()` invalidates every frame cache and refreshes enabled frames without dirtying the shared aura scan.
- Aura Frames owns the default-off `shared_background_color_enabled`; independent shared Frame BG, Bar BG, Buff Bar, Debuff Bar, Bar Text, and Timer Text colors; shared Bar Font and Timer Font selections; per-frame local Bar Font and Timer Font state; and default-on `sync_bar_bg*`/`sync_bar_color*`/`sync_text_color*`/`sync_text_font*` participation. One BG Colors participation selection applies both background colors, one Bar Colors selection applies the type-resolved Buff/Debuff fill, one Text Colors selection applies both text colors, and one Text Font selection applies both font roles. Colors resolve locally before the category's independent Buff or Debuff All the Colors override; fonts remain Aura-owned. The tab's Disable OOC Fade checkbox is a linked view of All the Colors' single global fade policy, not Aura-owned profile state.
- `af_background.lua` is the single frame-background owner for the module. It contains `M.resolve_frame_background()` and the shared-color/All the Colors policy, then exposes separate geometry adapters for addon-rendered shells and Blizzard-managed AuraContainers. The addon adapter owns backdrop state plus preallocated combat-safe count variants. Blizzard resets an empty managed AuraContainer to `1x1` after native flow layout, so Managed Icon Mode keeps one shell-anchored icon-cell base and two non-overlapping extensions partitioned around that cell. All three textures are peers in one container-owned layer: this avoids mixed-hierarchy alpha without anchoring a safe owner-level region to forbidden container layout. Active icons expand the background without protected size reads, count reads, or scripts. Managed Bar Mode keeps a configured-width first-row background and full-width native row extensions, preserving its shell insets and vertical expansion. Do not use AuraButton-owned pieces for Icon Mode: Blizzard clips their regions to individual icons and produces a segmented background. Managed preset and CDM presentation code supplies layout state but must not implement frame-background geometry itself.
- Aura Frames also registers `supports_ooc_fade = true`; each frame's saved Fade OOC value passes through Shared Colors so global `Disable OOC Fade` can temporarily restore full alpha without changing frame settings. Checking any frame-specific **Fade OOC** clears that global disable policy, synchronizes both linked global controls, and refreshes every fade-capable frame.
- `addon.DEFAULT_FADE_ALPHA` in `core/init.lua` is the project-wide Fade Alpha default and is `0.50`. Every Aura preset default, custom-frame template/new frame, missing-value fallback, and Fade Alpha slider Reset resolves through it rather than adding module/category literals.
- Focused Aura profile history and generated comparisons live in `internal_dev/tests_tools/cpu_profiles/af_cpu_profiles.md`; regenerate the normalized comparison with `internal_dev/tests_tools/cpu_profiles/analyze_af_cpu_profiles.ps1`.
- `aura_event_bucket` remains `0.20s`. Raising it would reduce scan/render frequency only by delaying real aura appearance/removal updates, so treat any future increase as a visible-latency experiment, not a low-risk CPU cleanup.
- Visible-icon ticker cost scales with `aura_visible_icon_tick`; treat the three measured choices (`0.10s`, `0.15s`, `0.20s`) as a CPU/visual-cadence tradeoff, not a per-tick optimization win.
- `render_aura_map()` stores `frame._display_count`; `tick_visible_icons()` should tick only displayed pooled icons, not the full pool.
- Aura Frames visible-icon ticker is managed on demand by `M.refresh_visible_icon_ticker()` / `M.ensure_visible_icon_ticker()`. It starts only when visible addon-rendered icons need timer/bar/preview/CDM cooldown updates and cancels itself when no frame needs ticking. The ticker must recheck `frame.icons` on every callback because a visible frame can transition to a managed backend without an addon-owned icon pool while a previously started ticker is still alive.
- CDM refresh scheduling is centralized in `M.queue_wow_cooldown_refresh(profile)` (`af_main.lua`). Use profiles `"immediate"`, `"startup"`, `"settings"`, `"hook"` instead of local timer chains. Blizzard emits no frame event when its settings UI saves category/order edits; one runtime-installed `hooksecurefunc` post-hook on public `C_CooldownViewer.SetLayoutData` queues the settling-aware `"settings"` profile so both the source and destination addon frames rebuild even when WoW settings were opened directly.
- CDM cooldown transport is viewer-independent. Effective saved category/order comes from a read-only `securecallfunction` call to `CooldownViewerSettingsDataProviderMixin.GetOrderedCooldownIDsForCategory()` and is copied immediately into addon-owned storage; this is necessary because public `C_CooldownViewer.GetCooldownViewerCategorySet()` exposes the base category set before saved layout overrides. Spell metadata still comes from public `C_CooldownViewer.GetCooldownViewerCooldownInfo()`, and cooldown or charge timing comes from `C_Spell.GetSpellCooldownDuration()` / `GetSpellChargeDuration()` and their duration objects. Fall back to the public base category sets only when the provider is unavailable or empty across all four addon CDM categories during login; once any sibling category is populated, an empty category is authoritative so moving its final spell out does not restore stale defaults. Never walk Blizzard viewer children, hook `CooldownViewerItemDataMixin`, hook child Cooldown widgets, force Edit Mode visibility, call viewer update methods, or install viewer scripts. These interactions can taint Blizzard's forbidden `auraInstanceIDToItemFramesMap` and make `RegisterAuraInstanceIDItemFrame()` fail on `UNIT_AURA`.
- The user-facing CDM hide settings may alpha-hide the matching native viewer and disable its mouse only. When a hide setting is off, leave the viewer under Blizzard control except for restoring state LsTweeks explicitly alpha-hid; module disable restores that alpha/mouse state.
- CDM Blizzard-viewer hide settings must be applied for every CDM category on startup/reload, independent of whether the matching addon CDM frame is enabled.
- CDM cooldown icon grey state is based on real spell cooldown data and intentionally ignores the global cooldown.
- CDM cooldown mode layers a native AuraSlot over each addon cooldown cell. Blizzard hides the slot when its Aura ends, revealing the already-updating cooldown layer without addon inspection. Divine Protection on Utility remains the combat transition regression: cast out of combat, enter combat, let the active Aura expire, and verify the cooldown appears immediately.
- Manual CDM regression matrix: `internal_dev/tests_tools/aura_frames_cdm_regression.md`.


## Scanning, Rendering, Timers
- The obsolete Static/Long shared scanner and category buckets were removed in 2026-08. Managed presets and CDM active-Aura groups/slots own live selection; custom frames scan their configured AuraFilters; CDM cooldown mode builds cooldown entries from public CDM metadata and spell duration APIs.
- `update_auras()` owns custom frames and the hybrid CDM cooldown/preview path; fully managed presets return before its icon-pool gate. CDM cooldown child state, managed backend refresh, custom filters, previews, timer/bar metadata, display count, height, and ticker eligibility can change independently, so do not skip the whole update path without a narrow proof.
- If Aura performance work reopens, profile `render_aura_map()`, `add_cooldown_viewer_category_entries()`, and `scan_custom_aura_map()` around the regressed row.
- Each custom/CDM frame owns its `_aura_map`; custom frames render Aura entries, while CDM uses it only for the cooldown layer and synthetic preview. Native CDM groups/slots never write active Auras into this map.
- Sorted unit-aura ID results are shared in `af_render.lua` only for non-CDM preset rendering; invalidate them through `M.clear_sorted_aura_ids_cache()` when aura data changes. CDM cooldown maps must bypass `C_UnitAuras.GetUnitAuraInstanceIDs()` entirely and render directly in `cdm_order`: WoW 12.1 can reject that unit-aura API as secret when a tainted CDM refresh reaches it.
- `M.invalidate_aura_scan_caches()` invalidates custom and sorted scan caches. There is no pending unified-scan dirty state.
- `render_aura_map()` reuses timer behavior for preset frames and caches timer behavior by category for custom frames during each render. Keep timer behavior resolution centralized; do not reintroduce per-icon timer behavior lookups.
- The render display-signature skip is intentionally conservative. It must be blocked by test previews, secret values, `scan_remaining`, unstable timing, or changed identity/visual/cooldown/stack/order data to avoid stale icon visuals.
- Frame-local runtime config cache is shared between `update_auras()` and layout setup for scalar/layout values, including copied scalar color components. Invalidate it through existing preset/custom settings updates, resize refresh, profile/reset refresh, and module re-enable refresh paths instead of adding a broad global cache.
- `af_icon_layout.lua` owns Aura frame content-height calculations through `M.get_aura_frame_height()`. Keep bar, icon, timer, padding, wrapping, and growth dimensions there; `update_auras()` only supplies current layout/runtime state and applies the stable height result. When no layout cache exists, preserve the compatibility 44px-per-icon fallback until `setup_layout()` rebuilds cached geometry.
- `af_background.lua` preallocates one addon-shell background texture per display count when `af_icon_layout.lua` completes an out-of-combat layout pass. In combat, `M.update_combat_background()` switches only the matching texture's visibility while the shell backdrop stays transparent; do not resize, reanchor, or create these variants in combat.
- Render helpers guard stable visual setters where practical; timer countdown and bar progress must continue updating live.
- Custom frames are AuraFilters-driven, not whitelist-driven. They scan with `C_UnitAuras.GetAuraDataByIndex("player", i, M.get_custom_aura_filter(entry))`.
- Custom frames can contain mixed static, short, long, and debuff entries. Bar/timer rendering and visible-icon ticking must treat `entry.category == "static"` as static per icon; do not rely only on `frame.category == "static"` for custom frames.
- Custom helpful scan classification must use `DoesAuraHaveExpirationTime()` and then the previous custom entry category before defaulting unreadable combat-entry timing to short; otherwise static custom bars such as Devotion Aura can empty when the custom scan cache rebuilds on `PLAYER_REGEN_DISABLED`.
- Preserve/snapshot the custom frame's previous `_aura_map` inside `scan_custom_aura_map()` before wiping it when the custom scan cache is being built or extended, so combat-sensitive rescans retain old category/timing fallbacks without copying old maps on the steady cached path.
- Custom scan results are cached by `aura_filter` plus threshold and lazily extended for larger frame limits; aura-affecting events clear the cache.
- Narrowing custom scans from `UNIT_AURA` payloads remains higher risk because custom filters/modifiers, secret values, full updates, and threshold/category changes can invalidate a simple affected-aura path.
- Use a central Aura dispatcher or invasive CDM rewrite only when a focused profile shows a material regression or a concrete behavior issue gives a narrower target.
- Timer text enable/format behavior is centralized in `af_functions.lua` via `M.get_timer_behavior()` and `M.is_timer_text_enabled()`, with formatting in `af_render.lua`: 100d+ uses whole days; 1d–99.9d, 10h–<24h, and 10m–<60m use fixed one-decimal labels; 1h–<10h uses fixed `hmm` fields including `00m`; 1m–<10m uses fixed `mss` fields including `00s`; sub-minute values use fixed decimal seconds. Long timers are right-aligned inside a fixed slot so format changes do not shift their trailing edge.
- Floating-point preview boundaries route through `M.normalize_aura_timer_remaining()` in `af_functions.lua`; do not add local epsilon patches.
- `af_test_aura.lua` owns one generic countdown/stack preview for every Aura frame. Restored saved previews initialize paused so the button offers Play after reload, while manually enabling a preview starts it. Fully managed presets use one shell-owned mock and an independent shell-owned Frame BG cell, leave real AuraContainer content active, and never inject synthetic data or addon frames into Blizzard groups. The global control temporarily enables previews on every enabled frame without replacing individual settings.


## Aura Cancellation
- Static / Long Buffs calls `AuraButton:SetCancelAuraButtons("RightButtonUp")` inside both managed group initializers. Blizzard's intrinsic secure click path calls `C_UnitAuras.CancelAuraByInstanceID()` and owns combat/restriction enforcement; do not attach addon click scripts or inspect its Aura data.
- Custom-frame cancellation is plain right-click, out of combat only, and only for real cancelable player buffs. Do not add in-combat custom cancellation without a secure-button redesign.
- Addon aura icons are plain frames, not secure aura buttons.
- Never pass `obj.aura_index` directly to `CancelUnitBuff`; in LsTweeks it stores `auraInstanceID`, while `CancelUnitBuff("player", index, filter)` requires the current positional buff index.
- On custom-frame click, reject cheaply first: combat lockdown, nonnumeric aura identity, test preview, spell cooldown, or disallowed frame/source.
- Allowed sources are custom frames when the clicked icon resolves to a current cancelable player buff.
- Treat a fresh `C_UnitAuras.GetBuffDataByIndex("player", i, "HELPFUL|CANCELABLE")` scan as authoritative. Cancel only when the scan finds the clicked `auraInstanceID`.
- Ignore unsupported states silently, then queue a normal aura refresh after a successful cancel attempt.
- `CancelUnitBuff` is restricted and `#nocombat`; secure templates support modifier attributes and `cancelaura`, but combat-safe support would require secure action buttons and careful out-of-combat attribute updates.
- Non-goals: modifier-gated cancellation, in-combat custom cancellation, cancellation from Short/Timed/Debuff or CDM frames, and global keyboard-only cancellation.


## Aura Tooltips
- 2026-08-15 in-game acceptance: managed helpful-buff and Debuff native tooltips display both in combat and out of combat. This validates the explicit `SetHideTooltipInCombat(false)` policy; managed Aura data remains entirely inside Blizzard's AuraButton tooltip path.
- Default safety requirement: useful descriptions are retained only when `C_TooltipInfo` data can be fully copied and validated; first-seen restricted combat effects may fall back to name/duration.
- Renderer architecture, secret-data rules, taint evidence, and shared regression contracts are owned in `../functions/tooltip.md`. Default Aura hover uses one addon-owned plain tooltip with guarded cached/basic lines. The reload-scoped `tooltipdebug native-on` experiment instead delegates untouched unit/Aura-instance arguments directly to Blizzard's global secure setter before any cache work.
- Visible custom icons and CDM addon-rendered cooldowns use a two-retry tooltip prewarm for late-loading data and the pre-combat attempt on `PLAYER_REGEN_DISABLED`. Managed CDM active Auras use Blizzard native tooltips. Cache both Aura-instance and reusable spell aliases for addon-rendered entries; clear Aura-instance keys on `PLAYER_ENTERING_WORLD`, retain reusable spell keys, and clear everything on reload/logout.
- Combat tooltip fallback must treat a safe remaining/expiration value as timed even when the restricted aura scan has no readable total duration; show its remaining countdown and omit unavailable total duration instead of labeling it permanent.
- Aura tooltip cache keys must stay numeric and non-secret (`auraInstanceID`, `spellID`). Do not key caches by `aura_name`; in restricted aura contexts it can be a secret string, and indexing an addon table with it causes `attempted to index a table that cannot be indexed with secret keys`.
- Aura-specific in-game acceptance and the native experiment procedure live in `../functions/tooltip.md` `## Validation`.


## Position, Drag, Resize
- Aura frame positions are stored as unscaled UIParent-center coordinates: `SetPoint("TOPLEFT", UIParent, "CENTER", pos.x / scale, pos.y / scale)`. Chosen because center-relative values are small and resolution-independent; do not switch to BOTTOMLEFT origin without updating defaults, saved positions, and slider ranges together.
- CDM default positions are dynamic: new/missing CDM positions are placed outside the current main GUI right edge with a 32px gap via `M.refresh_cdm_default_positions()` / `M.apply_cdm_default_positions_to_db()`.
- New custom frame default positions also use the current main GUI right edge with a 32px gap; existing saved/profile custom positions are not overwritten.
- Use `M.apply_frame_position()`, `M.read_frame_position()`, `M.sync_frame_position_to_db()`, `M.apply_saved_frame_position()`, and `M.sync_frame_position_from_drag()` rather than branching on preset vs custom manually.
- Drag/resize state is centralized through `M.start_frame_drag()` / `M.stop_frame_drag()` and `frame._is_user_positioning`. Managed preset resize completion reapplies the saved shell width to already-created native bar buttons and includes width in the presentation signature so both bar rows and icon wrapping refresh without rebuilding AuraGroups.
- Managed Move Mode draws a hybrid outline with four AuraContainer-owned textures for presets and CDM Aura mode: passive edges are one-pixel translucent gold while the safe interactive edge is three-pixel full gold, making the mover visually distinct. Configured shell width supplies the horizontal bounds while AuraContainer supplies the secret-derived vertical extent without exposing it to Lua, so CDM outlines expand as native groups gain icons even though the addon-rendered CDM map is empty in Aura mode. Shell `OnSizeChanged` refreshes both outline and background width OOC, and one-pixel edge overlap prevents corner seams. DOWN/LEFT/RIGHT layouts keep one 12px top drag strip centered across the thick top edge plus a top-right resize grip; UP uses the thick connected bottom edge and bottom-right grip. `M.MOVE_BORDER_COLOR` owns the shared outline, grip border, and three overlay grip marks; the marks sit above a dark contrast tile instead of relying on low-opacity Blizzard artwork. The frame-settings Move Mode checkbox and label show `Disables OOC Fade` because positioning forces full alpha. Do not restore full-shell hit areas, container-size polling, Aura events, container scripts, or addon frames anchored to AuraContainer.
- Aura frames own one shell-parented `frame.move_handle`, shown as a thin border only during Move Mode. Addon-rendered frames use four 8px inward hit areas; CDM hybrids use an outward top drag strip so native Aura buttons cannot intercept the frame-title tooltip. All mover targets share the drag path and show the title through the owned tooltip, while the center remains free for aura interaction. The bottom and right generic mover hit areas stop before the bottom-right 16px square, reserving that corner exclusively for the explicitly mouse-enabled resize grip. The border does not reserve layout space or depend on growth direction. Interactive addon frames must remain owned and anchored only by the addon shell: anchoring an ordinary addon frame to AuraContainer inherits `UntrustedLayoutScriptExecution` and WoW rejects `SetPoint()` even out of combat. The managed Icon background has one narrow exception supported by Blizzard FrameXML: a noninteractive clipping frame created before AuraGroup registration with `DisableUntrustedLayoutScriptsTemplate`, containing only background textures and no scripts.
- All frame types, including managed 12.1 AuraContainer presets, route saved scale and matching unscaled-coordinate re-anchoring through `M.apply_aura_frame_shell_transform()`; runtime refreshes, especially CDM refreshes, must not reapply saved anchors, scale, size, layout, or height while the user is positioning.
- `update_auras()` guards stable frame-shell setters for scale, position, size, height, alpha, backdrop, and move-shell visibility.
- Move Reset uses shared `addon.CreateMoveResetButton()` through the Aura Frames wrapper and `M.reset_frame_move_placement()`. It resets position/width, not Move Mode.


## Profiles And Reset
- Aura Frame Profiles live under `M.db.profiles`; `af_profiles.lua` owns the explicit snapshot and runtime apply hook, while shared CRUD/storage lives in `../functions/profiles.md`.
- Applying an Aura Frame profile replaces `M.db.custom_frames`, creates missing custom runtime frames, then runs reset refresh; shared CRUD, copy, and combat-gate behavior lives in `../functions/profiles.md`.
- General reset uses `CreateModuleReset(..., opts)` with checked-by-default **Keep Profiles**. When unchecked, `profiles` and `last_profile_name` must be cleared and cached profile UI refreshed.
- If reset replaces `custom_frames`, remove orphan runtime frames and stale controls, then rebuild the Frames tree/content if present.
- Custom-frame deletion removes its runtime frame/events/fades, DB entry, controls, and custom aura scan cache; the Frames tree chooses the visible fallback selection.
- Aura Frame profiles follow the shared unreleased-profile policy in `../functions/profiles.md`; incompatible local snapshots are replaced, not migrated.
- Profiles and reset include Aura-owned shared frame/bar backgrounds, Buff/Debuff bar-fill colors, Bar/Timer fonts, and every built-in/custom participation selection.


## GUI
- `af_gui.lua` owns the shell: tabs are **General**, **Frames**, **Shared BG Colors**, **Profiles**.
- `M.BuildSettings()` stays as the tab-shell coordinator and routes through local helpers plus a small `context` table.
- `af_gui.lua` routes its Profiles tab through the shared Profiles-tab factory. Timer and Stack font controls use the addon-wide catalog and dropdown factory in `functions/font_catalog.lua`. `M.build_general_tab` and `M.build_frames_tab` remain exported because they live in separate Aura Frames GUI files and are called by the shell.
- `af_gui_tree.lua` owns the Frames sidebar groups: **Buffs**, **WoW Cooldown**, **Filters**.
- `af_gui_frame_builders.lua` owns General, preset/CDM, custom settings, and custom filter panels.
- Entering a frame's Move Mode enables its Frame BG for visibility unless that frame has a saved `move_bg_opt_out` preference. Manually unchecking Frame BG records the opt-out; manually checking it clears the opt-out. Presets store `move_bg_opt_out_<category>` and custom frames store `move_bg_opt_out`, and both profile schemas retain the preference.
- `af_gui_shared_bg_colors.lua` owns the Aura-shared color/font controls and reusable participation matrix rows.
- Aura Frames follows `../functions/layout_grid.md`; its frame settings use repeated in-cell stacks and keep color pickers in dedicated grid columns with module-owned placement data.
- In CDM panels, the first-column top stack is Enable, Hide WoW, then Growth Direction in the fourth visual slot so the dropdown title has clear space; row 6 stacks Tooltip beneath Cooldown Mode when that mode is available. Other panels keep Growth beneath Tooltip with the same title clearance. Test Aura occupies the second column beneath Frame BG Color. Growth stays visible in both modes and refreshes between the independently saved Icon and Bar values when Bar Mode changes.
- The Shared BG Colors tab has **Frame Name**, **BG Colors**, **Bar Colors**, **Text Colors**, and **Text Font** columns. Picker rows are Frame BG/Buff Bar/Bar Text/Bar Font, then Bar BG/Debuff Bar/Timer Text/Timer Font; `COLOR_PICKER_ROW_1_Y` and `COLOR_PICKER_ROW_2_Y` are the shared vertical layout knobs. Each frame has one participation checkbox per settings column. Bar Font and Timer Font remain selectable while live sharing is disabled; each has an **Apply All** action that copies only that selected font to the local setting of every built-in and custom frame, refreshes runtime text, and does not change live-sharing enablement or participation.
- Disable OOC Fade and the global test-aura control remain active when shared settings are disabled or colors are globally overridden; individual test-aura controls remain in the Frames tabs. Shared pickers and participation controls require **Enable** and become inactive only when All the Colors overrides both Buff and Debuff groups; with one group overridden they remain editable for the other. BG Colors participation also makes the frame background visible. Matrix slots refresh after custom-frame and profile/reset changes without rebuilding frames.
- Aura Frames tab and tree heights derive from `addon.main_frame:GetContentAreaSize()`, so the main settings window height in `core/main_frame.lua` is the single height knob.
- CDM controls are source-specific additions layered through `opts.build_source_controls`.
- Shared presentation controls stay in the common builder; use hooks only for real source-specific behavior.
- Timer and Stack selectors use the addon-wide font catalog in `functions/font_catalog.lua`. Bold availability comes from each shared font definition: **Game Default** is disabled and grey because it has no registered bold face, while selecting a capable font re-enables the control without discarding the saved Bold preference.
