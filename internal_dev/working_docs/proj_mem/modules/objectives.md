## Settings And Defaults
Important `objectives` keys:
- `collapse_campaign`: when true, starts Blizzard's Campaign module in the All Objectives tracker collapsed.
- `collapse_quests`: when true, starts Blizzard's Quests module in the All Objectives tracker collapsed.
- `collapse_achievements`: when true, starts Blizzard's Achievements module in the All Objectives tracker collapsed.
- `show_quest_log_count`: when true, shows accepted quest log count/capacity in the Quests objective section title.
- `show_quest_log_count_on_hover`: when true, shows the Quests section count only while hovering the Quests title.
- `show_tracked_achievement_count`: when true, shows tracked achievement count/capacity in the Achievements objective section title.
- `show_tracked_achievement_count_on_hover`: when true, shows the Achievements section count only while hovering the Achievements title.
- `customize_background`: when true, sets Blizzard's Objective Tracker Edit Mode opacity to `background_alpha`; when false, sets that opacity to 0.
- `background_color_enabled`: when true, shows the addon-owned center color block and enables the color picker.
- `background_alpha`: alpha applied to Blizzard's own All Objectives `NineSlice` background. Default `0.5`.
- `background_color`: RGB/alpha for the owned center color block over the All Objectives background. Default/reset is 25% gray at 75% alpha: `{ r = 0.25, g = 0.25, b = 0.25, a = 0.75 }`.
- `objective_tracker_offset_x` / `objective_tracker_offset_y`: saved All Objectives tracker offsets from its captured startup center anchor.
- `objective_tracker_move_mode`: when true, allows dragging All Objectives and highlights the All Objectives header text.
- `objective_tracker_snap_to_grid`: when true, rounds All Objectives offsets to the module's grid size.
- `objective_tracker_border`: optional explicit border override independent from `background_color_enabled`. When unset, the border is inferred on for non-default `background_color` and off for default `background_color`.


## Runtime Notes
### File Ownership And Settings UI
- `modules/objectives/ob_defaults.lua` owns default DB values plus shared `M.get_db()` / `M.is_runtime_enabled()` helpers. `ob_position.lua` owns All Objectives tracker offsets, move mode, snap-to-grid, Position settings UI, and position status fields. `ob_auto_collapse.lua` owns Auto-Collapse tracker metadata, settings UI, visibility runtime, and status fields. `ob_section_count.lua` owns Section Count settings, count APIs, title sync, event registration, and status fields. `ob_background.lua` owns background sizing, background color/opacity, owned border, Objective Tracker background hooks, and background status fields. `ob_main.lua` owns module lifecycle, settings-page composition, event bootstrap, and module status aggregation.
- Objective settings group chrome uses addon-wide `addon.CreateSettingsGroup()` from `functions/ui_helpers.lua`, matching the Audio Volumes gold outline and 24px grey title bar. Use it for the group/title shell instead of hand-building repeated BackdropTemplate/title blocks in feature files.
- Objectives settings page order is Position, Background, Auto-Collapse, then Section Count below Auto-Collapse; placement follows `../functions/layout_grid.md`, while content-sized group widths and section order remain module-owned.
- Objectives uses General, Tracker, and Profiles tabs. General owns the module reset with checked-by-default **Keep Profiles**; profile storage/UI follows `../functions/profiles.md`; Tracker retains the combined Position, Background, Auto Collapse, and Section Counts layout.


### Auto-Collapse
- Auto-Collapse tracker metadata lives in `TRACKER_DEFS` in `modules/objectives/ob_auto_collapse.lua`; it owns DB keys, labels, status keys, global frame names, and top-to-bottom UI order. Current order: Campaign, Quests, Achievements.
- Historical direct addon calls to section `SetCollapsed()` entered `ObjectiveTrackerModuleMixin:MarkDirty()` and the shared container's later `Update()` pass, which walks the secret-sensitive Scenario module. That path produced the delayed 2026-08-17 Void Incursion `ShouldShowMawBuffs()` failure. The visibility-only replacement avoided the call graph but left full-height layout gaps and could prevent later sections from appearing.
- Current code uses the visibility-only fallback: it hides only each configured section's `ContentsFrame`, overlays an addon-owned plus button, and never calls section or parent `SetCollapsed`. Blizzard retains the expanded section height budget, so empty space and delayed later sections remain accepted limitations.
- A 2026-08-23 no-reload snapshot after normal gameplay with this fallback kept Campaign, Quests, Achievements, parent, and Scenario `isCollapsed` and `contentsHeight` fields secure. This supports the fallback boundary but remains one observation rather than proof across every future client path.
- Why this initially appeared different: the failed section implementation was already next-frame deferred and combat-gated, so the clean 2026-08-22 comparison isolated direct-function `securecall` as the changed variable. The final boundary capture disproved the hypothesis directly: Quests `SetCollapsed`, `isCollapsed`, `dirty`, and `contentsHeight` were secure before `securecall`; immediately afterward `isCollapsed` was `tainted:LsTweeks`, while later Scenario layout showed `contentsHeight` tainted too. The no-`securecall` control kept all inspected fields secure, ruling out general Objectives background activity for this failure.
- Discovery lesson: QuestLogCollapse 1.5.6 revealed the missing secure-boundary hypothesis, but its implementation wraps the call in an addon-authored anonymous function and tests a wrapper that returns no explicit success value. LsTweeks copied no code: it instead passes Blizzard's method directly and verifies `IsCollapsed()` afterward. The general direct-function, clean-argument, no-assumed-return contract belongs in `project.md` `### Key WoW APIs And Lessons`.
- Native collapse gives Blizzard header-only `contentsHeight`, releases container budget for later modules, and restores Blizzard's normal plus/minus controls, but every tested addon-driven native path was unsafe. The rejected code, diagnostics, live evidence, and earlier visibility source are preserved under `internal_dev/working_docs/reference/objectives_auto_collapse_taint_2026-08/`.
- A file-local manual-open override prevents later apply passes from recollapsing a section the user expanded. A non-protected `HookScript` on Blizzard's minimize button clears/rearms the override after a real manual collapse. Keep hook guards and state file-local—never add custom fields to Blizzard frames.
- Track addon-hidden content separately from observed frame visibility. Setting/module disable restores only content LsTweeks hid; a section already hidden or natively collapsed by Blizzard or the user remains untouched. `/lst status objectives` reports `<section>_addon_hidden` and `<section>_contents_shown` for this boundary.
- A 2026-08-23 Auto-Collapse-on Incursion completed without a visible error but all 54 captured Scenario snapshots reported Campaign, Quests, and Achievements `isCollapsed` and `contentsHeight` as `tainted:LsTweeks`; parent and Scenario fields plus each section's `dirty` field remained secure. This strongly implicates the section collapse transaction even though repeated Scenario events displaced the initial boundary records from chat history. The collector now coalesces consecutive duplicates, limits the printed recent timeline to 90 entries, and repeats up to 20 critical session/marker/`securecall` records at the end.
- The matching Auto-Collapse-off control kept Objectives and its background hooks enabled, performed no post-reload `securecall`, completed without an error, and kept all inspected fields secure across 75 represented Scenario events. This isolates the tainted section state to Auto-Collapse rather than general Objectives background activity.
- Never programmatically collapse `ObjectiveTrackerFrame` itself; All Objectives collapse remains manual/Blizzard-owned and legacy `collapse_all` data is ignored.
- Unchecking an Auto-Collapse option restores only its addon-hidden contents. Disabling Objectives restores only visibility owned by Auto-Collapse, with combat deferral when required.


### Background And Position
- `ObjectiveTrackerFrame.NineSlice` is Blizzard's All Objectives background. The Objectives module post-hooks tracker updates only to correct the collapsed All Objectives container case and to let Blizzard priority content surface itself: when `ObjectiveTrackerFrame` itself is collapsed, LsTweeks forces the background to the header. It also watches Blizzard changes to `ObjectiveTrackerFrame.NineSlice:SetPoint()`; if Blizzard anchors the background under a `hasDisplayPriority` module while All Objectives is collapsed, LsTweeks yields that background layout to Blizzard after the collapse grace window. It must not force-expand the tracker from the hook or queued sync: that re-enters Scenario Objective Tracker layout under LsTweeks taint, and current Blizzard layout calls the secret-sensitive `ShouldShowMawBuffs()`. Ordinary section anchors are corrected back to the header and reported as `bg_blocked_anchor` instead of reopening All Objectives. When the tracker is expanded, Blizzard's normal Objective Tracker layout is fully in control. Disabling the module leaves Blizzard tracker updates untouched.
- The Position settings group owns move-mode/snap controls and X/Y offset sliders because those controls affect the whole All Objectives tracker frame, not either background layer. The Background settings group owns separate `WoW BG` and `Custom BG` toggles, Blizzard background alpha, `background_color`, and a Border checkbox. `WoW BG` mirrors Blizzard's Objective Tracker Edit Mode opacity control: checked sets opacity to `background_alpha`; unchecked sets opacity to 0. `background_alpha` controls Blizzard's real Objective Tracker opacity via Edit Mode when available, falls back through `ObjectiveTrackerManager:SetOpacity()`, and hooks the inner slider `OnValueChanged` for immediate drag preview because the shared slider callback is debounced. `background_color` controls an owned rectangular center color block because the current client did not expose a stable rounded-corner RGB tint path for the `NineSlice`; its alpha is edited in the shared color picker popup. `Custom BG` gates only the owned color block and color picker; Border stays enabled/clickable and can show independently. The owned color block lives on the tracker parent for alpha independence, sits behind `NineSlice` so Blizzard's line art stays visible, and hides `NineSlice.Center` while enabled so the color shows through. Overlay frame, texture, and anchor state live in an addon-owned weak table keyed by `NineSlice`; never store `_lstweeks_*` fields on the Blizzard frame. The color picker reset restores 25% gray at 75% alpha and enables/checks Border, including the border offset adjustment. `/lst status objectives` reports `bg_*` background diagnostics plus `bg_region_<n>_*` diagnostics for region name, type, draw layer, size, alpha, vertex color, blend, desaturation, texture, and atlas. Disabling the Objectives module hides only LsTweeks-owned color/border overlays, and background toggles use the owned queued sync; neither path may call `ObjectiveTrackerFrame:Update()`.
- Objective Tracker Edit Mode opacity uses a `0..100` display/storage value, while LsTweeks `background_alpha` is `0..1`; convert at the API boundary only. `bg_edit_mode_state=edit_mode:<n>` reports the Edit Mode/manager percent written, and `bg_nineslice_alpha=<n>` reports the live `NineSlice` alpha. If `WoW BG` is checked and status shows `bg_wow_enabled=true`, `bg_alpha=0.5`, but `bg_edit_mode_state=edit_mode:0` / `bg_nineslice_alpha=0`, the checked path is still passing an explicit zero override. The 2026-06-28 regression was caused by `show_blizzard_background and nil or 0`; never use Lua `and/or` ternary form when the intended true branch is `nil`.
- Border presence is controlled only by `objective_tracker_border`; a non-default saved background color must not implicitly create the border. Border enable owns the automatic `-12, -5` tracker shift. When the border is absent, startup or border disable clears that shift only if both saved offsets exactly match the old automatic pair, preserving every other user-selected position.
- Tracker positioning has one ownership path: nonzero saved offsets capture Blizzard's anchor, apply the LsTweeks position, and mark it owned; zero offsets and module disable route through one release helper that restores only an actually applied position. Enabling Objectives with zero offsets must leave Blizzard anchoring untouched. Move Mode is also lazy: when disabled it must not call `SetMovable`, register drag input, attach tracker script hooks, or change mouse state; those Blizzard-frame mutations begin only after the user explicitly enables Move Mode. Never hook the tracker `OnUpdate`: an insecure handler can taint Blizzard's Objective Tracker layout and make Maw Buffs secret-Aura reads fail. Drag sampling runs only on an addon-owned frame while a drag is active.
- Background sizing treats `ObjectiveTrackerFrame` collapsed state as header-only using `IsCollapsed()`, `isCollapsed`, or `collapsed`, clears the stale bottom anchor when possible before retargeting to the header, and schedules one short follow-up sync after tracker collapse changes to avoid races with Blizzard's own late tracker update. The background `SetPoint` hook corrects ordinary collapsed anchors immediately, with a guard around LsTweeks-owned `SetPoint` calls; the collapse grace window delays yielding to Blizzard priority content only, not ordinary-anchor cleanup. `/lst status objectives` reports `bg_anchor`; `bg_anchor=blizzard` means Blizzard owns expanded layout and `bg_anchor=blizzard_priority` means Blizzard owns a collapsed priority layout. It also reports `bg_point_hook`, `bg_force_expand` (legacy field; `suppressed:<module>` records a prevented addon-driven expand), `bg_blocked_anchor`, `bg_force_expand_grace`, and `bg_module_<n>_*` diagnostics for Blizzard module name, priority, shown/collapsed/displayable state, public/raw content heights, raw `hasContents` / tried / skipped fields, state, and last block when investigating world-event objectives.
- Shared Colors resolves only the owned custom center block RGBA inside the existing combat-deferred apply path. It never enables `Custom BG`, changes the owned border, or changes Blizzard background opacity.


### Section Count
- Section Count checkboxes enable counters on Blizzard's own module header text, with a per-section `On Hover` checkbox to make each counter hover-only. Quests show bare `x / y` accepted quest log capacity by scanning `C_QuestLog.GetInfo()` over `C_QuestLog.GetNumQuestLogEntries()` and excluding headers, hidden/internal entries, tasks, bounties, and world quests before comparing against `C_QuestLog.GetMaxNumQuestsCanAccept()`. Do not use the second `GetNumQuestLogEntries()` return directly for this display; it can include entries that exceed the accepted-quest cap. Achievements show bare `x / y` tracked achievement capacity from `C_ContentTracking.GetTrackedIDs(Enum.ContentTrackingType.Achievement)` plus `Constants.ContentTrackingConsts.MaxTrackedAchievements`.
- Section Count display formatting is centralized in `ob_section_count.lua` constants `COUNT_TEXT_FORMAT` and `TITLE_COUNT_FORMAT`.
- When a Section Count checkbox is off, or when `On Hover` is enabled and the header is not hovered, Objectives must not keep rewriting that section title. It should only restore Blizzard's base title once if LsTweeks had previously applied a counter, so it does not fight Blizzard refreshes or another title addon while the option is disabled or idle.
- Section Count is event-driven and does not hook objective tracker layout/update methods. It registers quest title events only while `show_quest_log_count` is true and achievement title events only while `show_tracked_achievement_count` is true. Count scans happen on owned events for always-visible counters, or only while the matching section header is hovered for hover-only counters; syncs cache the displayed count signature and skip `SetText` when the count text has not changed.
- Current generated Blizzard docs list the tracked achievement cap as 10. Quest-log capacity is read through `C_QuestLog.GetMaxNumQuestsCanAccept()` instead of hardcoded.


### Lifecycle And Combat Deferral
- Protected Objective Tracker mutations are combat-deferred through `M.defer_objectives_combat_update()` in `ob_main.lua`. Position apply/restore, move-mode tracker changes, native Auto-Collapse changes, background color/opacity writes, background anchor correction, border sync, and tracker `Update()` replay after `PLAYER_REGEN_ENABLED`; settings values still save immediately during combat.
- Initialization can race `ObjectiveTrackerManager:Init()`, which runs after both `PLAYER_ENTERING_WORLD` and `VARIABLES_LOADED`. Remove the `ADDON_LOADED` or delayed `PLAYER_ENTERING_WORLD` apply paths only after in-game testing proves they are redundant.
